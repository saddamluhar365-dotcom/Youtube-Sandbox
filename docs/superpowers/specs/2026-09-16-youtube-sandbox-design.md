# YouTube Sandbox Phase-1 Design

## Goal
Build a Render-deployable sandbox that accepts a recipe-short job, generates 9 connected 10-second AI video clips through an authorized fal.ai key pool, creates/obtains ambient ASMR audio and background music, assembles a 90-second 9:16 MP4 with FFmpeg, validates the result, and exposes the final artifact for inspection. YouTube upload is explicitly out of scope for Phase-1.

## Current repository state
The repository `saddamluhar365-dotcom/Youtube-Sandbox` currently contains only a minimal README. The design therefore treats this as a new project rather than modifying an existing pipeline.

## Target workflow
Topic -> scene planner -> 9 scene prompts -> fal.ai video jobs -> clip downloads -> ambient/ASMR audio -> background music -> per-clip audio/video assembly -> 90-second final assembly -> media validation -> downloadable output.

## Content constraints
- Format: 90 seconds total.
- Structure: 9 separate 10-second clips.
- Visual style: Ghibli-inspired 2D village atmosphere.
- No dialogue and no narration.
- Audio: environmental village/cooking ASMR plus soft background music.
- Each 10-second clip must contain 3-5 meaningful visual beats and remain connected to the previous/next clip.
- Target output: 1080x1920 MP4, suitable for Shorts.

## API and security constraints
- fal.ai API keys are supplied through Render environment variables, never committed to Git.
- The application supports a configured pool of fal.ai keys and tracks failures/rate limits without attempting to bypass provider limits.
- Gemini is used for planning only if its environment variable is configured.
- No API key values are accepted in ordinary request payloads or persisted in job records.
- No YouTube OAuth, YouTube upload endpoint, publishing, scheduling, or channel write capability is included in Phase-1.

## Storage and execution
- Render service is the orchestration/API runtime.
- Temporary generated media is stored under an isolated job workspace and cleaned after retention rules permit.
- Final artifacts are served through a controlled download endpoint; production persistent object storage can be added later without changing pipeline interfaces.
- FFmpeg is required at runtime and must be checked at startup/health time.

## API surface
- `GET /health` — service/dependency readiness without exposing secrets.
- `POST /api/v1/jobs` — create a generation job from a topic and optional style/recipe constraints.
- `GET /api/v1/jobs/{job_id}` — retrieve status and validation results.
- `GET /api/v1/jobs/{job_id}/output` — download the final MP4 only when validation succeeds.
- `POST /api/v1/jobs/{job_id}/cancel` — cancel a queued/running job and clean temporary resources.

## Job states
`queued`, `planning`, `generating_clips`, `generating_audio`, `assembling`, `validating`, `completed`, `failed`, `cancelled`.

## Quality gates
A job cannot become `completed` unless:
1. Exactly 9 clips exist.
2. Every clip is readable and has the expected duration within a defined tolerance.
3. Final output is 1080x1920.
4. Final duration is approximately 90 seconds within a defined tolerance.
5. FFmpeg can decode the complete final file.
6. Audio exists, is decodable, and does not contain dialogue/narration generated by the application.
7. Output file size is non-zero and within configured safety limits.

## Error handling
- Retry transient fal.ai/network failures with bounded exponential backoff.
- Do not retry permanent validation or authentication failures indefinitely.
- Mark unhealthy keys temporarily unavailable and continue with other authorized keys.
- Fail the job with a structured reason after configured retry/timeout limits.
- Never expose provider API responses containing secrets in public job responses.

## Phase-1 non-goals
- YouTube upload.
- Automatic publishing or scheduling.
- Analytics/learning loop.
- Thumbnail generation.
- Multi-user authentication/billing.
- Unlimited free-generation claims or quota circumvention.

## Testing strategy
- Unit tests for scene validation, key routing, state transitions, media validation, and FFmpeg command construction.
- Integration tests with mocked fal.ai/Gemini providers.
- A real-provider smoke test must be opt-in via Render environment configuration and must generate only one 10-second clip before enabling full 9-clip jobs.
- End-to-end sandbox acceptance test: one topic produces a validated 90-second MP4 without any YouTube API dependency.
